# Architecture

Living document. Update this whenever a structural decision changes (new module,
new data flow, new storage layer, etc.) — keep it in sync with the actual code.

## Overview

MoneyMatter is a **Wails v2** desktop app: a Go backend renders a **React + TypeScript**
frontend inside a native webview. Single binary, no separate server process.

```
main.go / app.go (Go)  <-- Wails bridge (wailsjs) -->  frontend/src (React)
```

## Tech Stack

- **Backend**: Go 1.25, Wails v2. `modernc.org/sqlite` is present in go.mod (indirect) —
  local SQLite storage is anticipated but not yet wired into `app.go`.
- **Frontend**: React 19 + TypeScript, Vite 7, Tailwind CSS 4 (via `@tailwindcss/vite` plugin).
- **Icons**: `lucide-react` exclusively, as `<Icon size={n} className="..." />` components colored via `currentColor` (Tailwind text-color classes on the icon or a wrapping element). Material Symbols Outlined (Google Fonts) was removed entirely — no `material-symbols-outlined` class or font link remains. Use existing icon component names from `Header.tsx`/`Sidebar.tsx` for consistency (e.g. `LifeBuoy` for "Support" everywhere) rather than picking new near-duplicates per component.
- **Bridge**: `frontend/wailsjs/` — auto-generated bindings (`go/main/App.*`, `runtime/*`) that expose Go methods to the frontend and vice versa. Regenerated by `wails build`/`wails dev`, don't hand-edit.

## Frontend State & Data Flow

- `App.tsx` is the single source of truth for top-level UI state (`currentTab`,
  `currentProfile`, `theme`) and passes it down as props to `Header`, `Sidebar`.
- No global state library (no Redux/Zustand/Context) yet — plain `useState` + prop
  drilling. Revisit if state sharing gets deeper than Header/Sidebar/App.
- Theme: `getSystemTheme()` (exported from `Header.tsx`) resolves the OS
  `prefers-color-scheme`, falling back to `'light'`. `App` seeds its `theme` state
  from it; theme is passed down as a prop and changed via `onThemeChange`. See
  `docs/DECISIONS.md` for the placement/icon decisions.
- Styling: Tailwind utility classes computed conditionally per `theme === 'dark'`
  checks (no `dark:` variant strategy configured) + CSS variables in `theme.css`
  (`:root` = dark palette, `.theme-light` = light palette overrides).

## Backend

- `App` struct in `app.go` holds `ctx` and exposes bound methods (currently just
  `Greet`, a template leftover) — this is where future Go methods for file
  import/export, SQLite access, etc. should be added, then re-exposed to the
  frontend via `wailsjs/go/main/App.*` (regenerated automatically).
- No persistence layer implemented yet. `modernc.org/sqlite` being in go.mod
  signals the intended storage engine per `docs/INSTRUCTIONS.md`'s import/export
  and record-tracking goals, but no schema/DB code exists yet.

## Planned Direction (from docs/INSTRUCTIONS.md)

Import/export of financial records (JSON/XML), document management (payslips,
statements, tax forms), investment tracking, and expense analytics/charts are the
target feature set — none of this is implemented yet; current code is UI shell
(Header/Sidebar/Footer/App) with placeholder handlers (`console.log`).
